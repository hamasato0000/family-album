# コンテンツアップロードフロー（実装ベース）

現在の実装に基づいたアップロード処理のシーケンス図です。

## 概要

1. **アップロード開始**: クライアントがアルバムを指定してアップロードセッションを作成します。
2. **署名付きURL生成**: アップロードするファイル情報（ファイル名、MIMEタイプ）を送信し、S3へのアップロード用URLを取得します。
3. **S3アップロード**: クライアントが直接S3へファイルをアップロードします。
4. **非同期処理**: S3への保存をトリガーにLambdaが起動し、検証、サムネイル生成、DB更新を行います。

## シーケンス図

```mermaid
sequenceDiagram
    participant Client as クライアント
    participant API as APIサーバー
    participant DB as データベース (Prisma)
    participant S3 as S3 (Storage)
    participant Lambda as Lambda (Content Processor)

    Note over Client, API: 1. アップロード開始
    Client->>API: POST /albums/{albumId}/uploads<br/>{ content_count: N }
    API->>DB: e_activity作成
    API->>DB: e_upload作成 (status=pending)
    API-->>Client: { upload_id, ... } 返却

    Note over Client, API: 2. 署名付きURL生成
    Client->>API: POST /uploads/{upload_id}/contents<br/>{ contents: [{ filename, contentType }] }
    API->>DB: e_upload所有者・個数チェック
    API->>S3: 署名付きURL生成 (PUT用)
    API->>DB: r_content作成 (status=pending相当)
    API-->>Client: { contents: [{ content_id, presigned_url }] } 返却

    Note over Client, S3: 3. S3にコンテンツアップロード
    loop 各ファイル
        Client->>S3: PUT {presigned_url} (ファイル本体)
        S3-->>Client: 200 OK
    end
    Note right of Client: クライアントはアップロード完了後に<br/>画面遷移または完了待機

    Note over S3, Lambda: 4. Lambdaでコンテンツ検証・サムネイル生成
    S3->>Lambda: イベント通知 (s3:ObjectCreated)
    
    loop 各レコード処理
        Lambda->>DB: r_content取得
        Lambda->>S3: オブジェクト(画像)取得
        
        alt バリデーション (サイズ超過・形式不正)
            Lambda->>DB: r_content更新 (errorMessage記録)
        else 正常系
            Lambda->>Lambda: 画像検証・EXIF抽出
            Lambda->>Lambda: サムネイル生成 (sharp)
            Lambda->>S3: サムネイル保存 (thumbnails/{uploadId}/{contentId}.jpg)
            Lambda->>DB: r_content更新 (thumbnailPath, fileSize, takenAt等)
            Lambda->>DB: r_photo作成/更新 (width, height, exif)
        end

        Lambda->>DB: 完了判定 (全コンテンツが処理済みか確認)
        opt 全て完了 (completed + failed == expected)
            Lambda->>DB: e_upload更新 (status=completed)
        end
    end
```

## 補足: データモデル関係

- **e_upload**: アップロードセッション。`photoCount`, `videoCount` で期待するファイル数を保持。
- **r_content**: 個々のコンテンツ。Lambda処理完了時に `thumbnailPath` がセットされることで「完了」とみなされる。エラー時は `errorMessage` がセットされる。
- **r_photo**: 写真のメタデータ（EXIF, サイズなど）。`contentId` と 1:1 で紐づく。
